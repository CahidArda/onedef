---
title: CLI
description: A command-line tool with login, generated from the contract. It ships no handler code.
---

```ts title="cli.ts"
#!/usr/bin/env node
import { runCli } from '@onedef/cli'
import { rpc } from '@onedef/orpc/client'
import { contract } from './contract'

await runCli(contract, { transport: rpc({ url: 'https://api.acme.dev/api' }) })
```

Publish it with a `bin` entry, and every operation is a command:

```bash
acme songs list --q piaf --limit 20
acme songs get la-vie-en-rose
acme songs rename la-vie-en-rose --title "La Vie en rose"
acme songs delete la-vie-en-rose --yes
```

| | |
| --- | --- |
| commands and flags | from operations and input fields; `--help` uses your summaries |
| output | lists print as tables, with the next-page command; `--json` for scripts |
| destructive operations | ask for `--yes` |
| errors | print the code and message, exit non-zero |

The transport is any [client transport](/docs/clients): `rpc({ url })` for your backend,
`http()` for an [existing API](/docs/define/existing-api).

## Login

With `auth` in your config, the CLI gets `login`, `logout` and `whoami`:

```bash
acme login                # OAuth in the browser
acme login --with-token   # paste an API key
ACME_API_KEY=… acme …     # CI: credentials from the environment
```

`acme login` signs in like an MCP client: it discovers your authorization server from the
API, registers with CIMD (DCR as a fallback), and uses PKCE through a local callback.
Tokens refresh before they expire. Credentials live in `~/.config/acme/credentials.json`
(`0600`). See [Auth](/docs/guides/auth).

## An agent skill

`toSkillMarkdown(contract, { bin: 'acme' })` writes a `SKILL.md` that teaches an agent
working in a terminal to use your CLI.
